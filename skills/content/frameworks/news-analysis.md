# 框架：news-analysis（新闻解读 / 事件分析）

> 适用：新事件解读、行业动态分析、财报/发布会的「这意味着什么」。
> 输入：`ContentBrief`；输出：`ArticleDraft`（纯 Markdown，无 `:::` 标记）。

## 结构骨架

```text
1. 事件一句话 —— 30 字内说清发生了什么（谁、何时、做了什么、规模）
2. 关键事实   —— 3-6 条，每条带 fact_id 与来源；时间线排列
3. 背景脉络   —— 这件事的前史；为什么是现在发生
4. 影响分析   —— 对谁有利/不利、短期/长期分开说；标注哪些是推断
5. 值得关注   —— 接下来的观察指标 / 时间点
```

## 写作规则

- **事实与观点分离**：事实段落只陈述带 `fact_id` 的内容；观点段落明确用「我们认为/一种解释是」开头。
- **多方平衡**：涉及争议时，至少呈现两方立场及其原始表述（引用原话交给 native 层的 `:::quote`，写作层先写清出处）。
- **数字给参照系**：「增长 47%」要补「从多少到多少」或「同行为多少」。
- **不预测股价、不替人做结论**：给观察指标，不给投资建议。
- 时效声明：正文注明信息截止时间；后续反转风险高的推断要说明依据的脆弱性。

## 自审清单（批判 → 重写阶段逐项过）

- [ ] 第一段能独立成为一条合格的消息推送吗？
- [ ] 每条关键事实都能点开 `fact_id` 追到来源吗？来源可信度 ≥ 0.6 吗？
- [ ] 推断和事实在文字上有明确分界吗？
- [ ] 有没有某个利益相关方的立场缺席？
- [ ] 数字都有参照系吗？
- [ ] 跑过 humanize 检测器，`passed: true` 了吗？

## Humanize 专项提示

新闻解读最容易踩的 AI 味：「值得注意的是」「不容忽视」「无疑将」「时代的浪潮」。改法：把评价换成具体机制——不说「这将重塑行业」，说「采购预算从 IT 部门挪到业务部门，中间商的报价模型得重算」。
