# 框架：opinion（观点文 / 立场文）

> 适用：表达明确立场的行业判断、反共识论证、方法论主张。
> 输入：`ContentBrief`；输出：`ArticleDraft`（纯 Markdown，无 `:::` 标记）。

## 结构骨架

```text
1. 立场亮相   —— 开篇直接给结论，不铺垫；标题就是立场
2. 反方最强   —— 先写对立面最有力的版本（钢人论证），不树稻草人
3. 论据推进   —— 2-4 个支撑论据：数据 / 机制 / 经验，逐层递进
4. 让步与边界 —— 承认立场失效的条件；写明「什么证据会让我改观点」
5. 可检验判断 —— 给出可证伪的预测或可执行的建议，收束
```

## 写作规则

- **立场一句话可复述**：读者转述你的观点时不需要加限定词。
- **钢人论证**：反方观点写成其支持者本人会认可的形式，再反驳。
- **论据分层标注**：事实（挂 `fact_id`）/ 推理 / 价值偏好，文字上分得清。
- **让步不是软弱**：明说立场的适用边界，比硬撑全面正确更有说服力。
- **不做人身攻击、不诉诸动机**：反驳观点本身，不猜对方为什么这么想。

## 自审清单（批判 → 重写阶段逐项过）

- [ ] 立场在 100 字内出现了吗？标题能独立承载立场吗？
- [ ] 反方被公平呈现了吗（其支持者会认吗）？
- [ ] 每个论据都能分清是事实、推理还是偏好吗？
- [ ] 写了「什么证据会让我改变观点」吗？
- [ ] 有没有为了显得客观而和稀泥（「各有道理」）？
- [ ] 跑过 humanize 检测器，`passed: true` 了吗？

## Humanize 专项提示

观点文最容易踩的 AI 味：「不得不说」「显而易见」「毋庸置疑」这类确定性填充词，以及「一方面…另一方面」的和稀泥结构。改法：断言强度与证据强度匹配——数据支撑的用强断言，个人偏好的直接写「我偏好」，不需要为有立场而道歉。
