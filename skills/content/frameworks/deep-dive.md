# 框架：deep-dive（深度长文）

> 适用：原理拆解、行业全景、系统讲透一件事的机制与边界。
> 输入：`ContentBrief`；输出：`ArticleDraft`（纯 Markdown，无 `:::` 标记）。

## 结构骨架

```text
1. 具象切口   —— 一个具体现象 / 问题引入，不从概念定义开始
2. 问题定义   —— 把模糊大话题切成 2-4 个可回答的子问题
3. 逐层拆解   —— 每个子问题一层；机制 > 现象 > 观点
4. 体系图景   —— 子问题之间怎么连接；整体如何运转；边界条件
5. 未决问题   —— 这套理解的失效点、开放问题、观察指标
```

## 写作规则

- **具象优先**：先现象后概念，先例子后抽象；「随着…的发展」开头直接毙掉。
- **机制解释**：每个主张回答「为什么会这样」，而不止「是什么」。
- **子问题尽力 MECE**：互相独立、合起来穷尽；做不到就明说切法是哪种。
- **深度递进**：每一层比上一层多回答一个 why，直到触到机制或证据边界。
- **置信度标注**：关键机制主张挂 `fact_id`；推断性内容写明推断依据。
- **不复述目录**：章节间靠逻辑递进衔接，结尾不复述各节小标题。

## 字数预算（word_target 参考）

| 部位 | 占比 |
|------|------|
| 具象切口 + 问题定义 | 15% |
| 逐层拆解 | 60% |
| 体系图景 | 15% |
| 未决问题 | 10% |

## 自审清单（批判 → 重写阶段逐项过）

- [ ] 开头是具体现象而不是宏大背景吗？
- [ ] 每个子问题都有明确答案吗（或明确说「目前未知」）？
- [ ] 有没有哪一层只有现象罗列、没有机制解释？
- [ ] 未决问题是真未决，还是懒得查？（后者去查或删掉）
- [ ] 删掉任何一节，整体论证会受损吗？（不会 = 该节独立成文）
- [ ] 跑过 humanize 检测器，`passed: true` 了吗？

## Humanize 专项提示

深度文最容易踩的 AI 味：「综上所述」式循环总结，每节结尾把小标题扩写一遍。改法：结尾只回答「这套理解接下来怎么被检验 / 在哪失效」，把复述的空间让给新信息；段落之间用因果衔接而非「接下来我们来看」。
