# 框架：listicle（清单体）

> 适用：工具盘点、技巧合集、方法论清单、「N 个 …」结构。
> 输入：`ContentBrief`；输出：`ArticleDraft`（纯 Markdown，无 `:::` 标记）。

## 结构骨架

```text
1. 钩子与承诺 —— 一个具体场景说明为什么需要这份清单
2. 入选标准   —— 怎么选出来的；先给标准，再给名单
3. 条目正文   —— 每条：一句话定义 → 展开 → 怎么用 / 何时不用
4. 快速对照   —— 结尾极简回顾（表格或一句话总结），方便收藏
```

## 写作规则

- **条目可独立食用**：读者只看其中一条也有收获。
- **排序有意义**：按场景 / 难度 / 使用频率排，并在开头说明排序逻辑。
- **每条写「何时不适用」**：没有适用于一切的工具；只夸不贬是软广味。
- **数量克制**：宁缺毋滥；删掉后清单价值不受损的条目，就是凑数条目。
- **编号即结构**：靠编号提供秩序，不写「接下来介绍」「下面让我们看看」。
- 涉及价格、版本、兼容性的陈述挂 `fact_id`。

## 字数预算（word_target 参考）

| 部位 | 占比 |
|------|------|
| 钩子 + 入选标准 | 15% |
| 条目正文 | 75% |
| 快速对照 | 10% |

## 自审清单（批判 → 重写阶段逐项过）

- [ ] 入选标准写在名单之前了吗？
- [ ] 每条都有「何时不用」或局限说明吗？
- [ ] 标题数字与正文条数一致吗？
- [ ] 排序逻辑说清楚了吗？
- [ ] 随机删掉一条，清单价值受损吗？（不受损 = 该删）
- [ ] 跑过 humanize 检测器，`passed: true` 了吗？

## Humanize 专项提示

清单体最容易踩的 AI 味：每条都用「首先」「其次」「值得一提的是」开头，条目之间堆过渡句。改法：条目直接以对象或动词开头（「Figma 的自动布局」「关掉默认通知」），编号本身就是结构，过渡句全部删掉。
